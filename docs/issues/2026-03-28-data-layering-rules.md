# 研究资料与正式内容分层规则

## 问题目标

仓库里已经有大量研究稿、清单和正式数据。后续继续补内容时，必须明确哪些是“研究池”，哪些是“正式内容”，否则会出现资料混用、清单和页面不一致的问题。

## 问题现象

- docs 里已有大量 round / clean / pool 文件。
- 页面数据和研究清单之间需要持续同步。
- 如果没有分层规则，后续会很难判断某条内容是否已定版。

## 建议分层

1. 研究池：原始摘录、抽样锚点、待核内容。
2. 清单层：结构化总表、待定字段、优先级标记。
3. 正式层：页面直接消费的数据源。
4. 记忆层：长期规则、事故记录、流程约束。

## 预期结果

- 每条内容知道自己属于哪一层。
- 研究稿可以继续加，但不会污染正式数据。
- 页面同步时有明确的晋升路径。

## 验收标准

- 用户能区分“研究中”与“已定版”。
- 任何正式页面都只消费正式层或明确标记的待核层。
- 后续新增清单时不会破坏已有内容链路。
