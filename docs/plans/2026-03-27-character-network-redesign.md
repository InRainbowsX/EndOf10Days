# 人物馆关系画布重构方案

> **For Codex:** 如果进入实现阶段，先用 `superpowers:test-driven-development`，实现完成前用 `superpowers:verification-before-completion`。

**目标：** 把人物馆重构成一个可拖拽、可缩放、严格无重叠、默认完整入屏的关系画布。

**核心问题：** 当前版本的问题不是单个样式细节，而是布局模型错误。卡片位置、连线、标签、缩放、边界约束都在同一层做“视觉调参”，结果是布局脆弱、反复返工。

**推荐方案：** 采用“约束式关系画布”方案。人物节点建模为刚性矩形，拖拽和初始化布局都走同一套几何约束。连线与标签是依附层，不参与占位竞争。

## 1. 现状问题

当前版本有四个结构性问题：

1. **布局不是算出来的，而是摆出来的**
   现在主要靠预设坐标、缩放和肉眼微调。这样无法保证增加人物后仍然稳定。

2. **无重叠要求没有成为第一约束**
   视觉上“看起来分开”和数学上“矩形边界不相交”不是一回事。现有逻辑没有把无重叠作为统一约束。

3. **默认视图不受视口约束**
   当前画布和世界坐标之间关系不稳定，导致默认态可能出屏，用户还需要手动调整。

4. **视觉层和交互层混在一起**
   卡片、图钉、线、标签都直接占同一空间，没有主次和层级，导致一旦人物一多，阅读负担迅速失控。

## 2. 三种可选方案

### 方案 A：约束式四象限关系板（推荐）

把人物分到四个阵营象限，中间保留一个中心人物。每个卡片是固定尺寸矩形，初始化布局和拖拽都经过碰撞检测。

优点：
- 可严格证明不重叠
- 符合现在的人物馆分类结构
- 可继续保留拖拽和缩放
- 容易做出“证据板”视觉

缺点：
- 需要放弃完全自由布局
- 关系标签需要额外做避让

### 方案 B：分组泳道关系板

每个阵营是单独一列或一块区域，人物按层级自上而下排列，只允许在本组内拖动。

优点：
- 最清楚
- 几乎不会乱
- 最容易做严格约束

缺点：
- 没有关系网的张力
- 太像信息架构图，不像关系板

### 方案 C：力导向关系网 + 实时避碰

保留网状布局，用力导向算法让节点自动分散，再加碰撞修正。

优点：
- 更像真正的网络
- 更有动态感

缺点：
- 难以稳定
- 后续调试成本高
- 和“必须严格不相交、默认就清楚”冲突

**结论：** 选 `方案 A`。它在“可读性、可控性、可扩展性”之间最平衡。

## 3. 推荐方案细化

### 3.1 画布结构

人物馆画布拆成三层：

1. `Viewport`
   用户看到的可视区域。默认启动时必须完整收住主要人物，不允许出屏。

2. `World`
   内部逻辑坐标系。所有节点、线、标签都在这个坐标系里计算。

3. `Overlay`
   工具栏、辅助说明、后续可能的详情面板。这一层不参与人物占位。

### 3.2 节点模型

每张人物卡都抽象成一个刚性矩形：

- 固定宽度 `w`
- 固定高度 `h`
- 中心点 `(x, y)`
- 占位框 `R = [x - w/2, y - h/2, x + w/2, y + h/2]`

要求：

- 任意两张卡片 `Ri ∩ Rj = ∅`
- 任意卡片 `Ri` 必须完全落在安全可视区内

拖拽时：

- 先计算目标位置
- 再做轴向碰撞裁剪
- 如果往前会撞到另一张卡，就停在“刚好接触”的位置
- 如果往前会超出边界，也停在边界

这意味着：
- 不允许穿透
- 不允许压边
- 不允许被拖出屏幕

### 3.3 布局逻辑

主画布固定为“五区”：

- 中心：齐夏
- 左上：主角团
- 右上：天堂口
- 左下：极道
- 右下：高位秩序 / 生肖

每个区内部再按三层排：

- 核心人物
- 次核心人物
- 补充人物

如果某区人物过多：

- 主画布只放核心和次核心
- 补充人物放到折叠组 `更多人物`

这样能保证主画布始终可读。

### 3.4 连线与标签

连线和标签要从“主角”降为“辅助层”：

- 连线从图钉或卡片顶部锚点出发
- 线分两级：强关系 / 普通关系
- 标签挂在连线中段，但必须避开卡片矩形
- 标签本身不参与拖拽，只跟随线更新

原则：
- 卡片优先
- 标签其次
- 线最后

不能为了展示更多关系牺牲卡片可读性。

### 3.5 默认缩放与平移

默认进入人物馆时，系统自动计算一个 `fit scale`：

- 保证主画布完整落进视口
- 保证边缘留安全带
- 用户可以缩小看全局
- 放大上限不能让内容重新默认溢出

平移允许保留，但只是在“已有合法布局”上浏览，不影响无重叠约束。

## 4. 视觉方向

这次不建议继续做“越像截图越好”的机械模仿，而应该抽取有效语言：

- 深褐底板
- 拍立得式人物卡
- 红色图钉
- 细纸签关系标签
- 旧纸、胶带、轻阴影

但视觉必须服从布局：

- 卡片尺寸统一
- 标签长度统一到几个预设档位
- 图钉锚点统一
- 不再让不同尺寸的卡片混用

## 5. 实施顺序

### 第一阶段：模型重构
- 把节点、边界、碰撞、缩放抽成独立逻辑
- 不再用视觉调参驱动布局

### 第二阶段：阵营布局
- 把四象限和中心区排稳
- 只保留核心人物进入主画布

### 第三阶段：关系层
- 重做连线和标签锚点
- 做标签避让

### 第四阶段：视觉层
- 重做卡片比例
- 重做图钉和纸签
- 收紧工具栏与背景细节

## 6. 验收标准

必须全部满足：

1. 任意两张卡片的外接矩形不相交
2. 任意卡片都完整落在可视安全区内
3. 默认进入人物馆时，主画布完整可见
4. 拖拽卡片时，接触到其它卡片或边界会立即停止
5. 关系标签不压住卡片主体
6. 主角团、天堂口、极道、高位秩序四区一眼可辨

## 7. 当前建议

下一步不要再做零散 UI 修补。直接进入：

1. 重写人物馆的坐标/碰撞系统
2. 将主画布人物数量压到一个可控范围
3. 再重做视觉

否则继续调样式，只会在错误模型上反复返工。
