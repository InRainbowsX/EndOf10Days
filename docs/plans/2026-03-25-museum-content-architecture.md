# 十日终焉博物馆内容架构方案（评审稿）

## 1. 文档目标

这份文档用于确定《十日终焉博物馆》的网站内容结构，不讨论具体 UI 细节，先解决三个问题：

1. 博物馆到底按什么逻辑组织内容。
2. 每个馆里每条内容该怎么写，字段如何统一。
3. 人物、事件、规则、真相之间如何互相跳转，同时不把用户绕晕。

这份方案的核心原则只有两条：

- `先清晰，再复杂。`
- `复杂关系分层表达，不一次摊平。`

---

## 2. 整体策展思路

基于现有内容和网上常见讲解方式，这个网站最适合做成 `1 条主脉络 + 4 个深度专题馆` 的结构。

推荐总结构：

1. `总馆`
2. `人物馆`
3. `事件馆`
4. `世界观馆`
5. `关系馆`

其中：

- `总馆` 是主导航和主时间脉络。
- `人物馆` 和 `事件馆` 是最核心的停留区。
- `世界观馆` 负责解释层和终局回收。
- `关系馆` 不是主入口，而是深度专题馆。

这不是一个“关系图网站”，而是一座：

`以终焉阶段为主脉络，以人物和事件为主体展品，以规则和真相为解释层，以关系为深度专题的线上博物馆。`

---

## 3. 总馆定位

### 3.1 总馆是什么

总馆不是普通时间线，也不是百科目录。

总馆应该是整个网站的 `终焉主脉络馆`，负责用最少的信息让用户理解：

- 故事如何推进
- 每段终焉的核心矛盾是什么
- 每段终焉最重要的人物和事件是什么
- 这一段留下了什么结果，并如何流向下一段

总馆承担的是：

- 入口
- 导航
- 脉络总览
- 向其他馆导流

### 3.2 总馆固定结构

总馆的每一个“终焉阶段”都统一使用以下字段：

| 字段 | 说明 |
| --- | --- |
| `range_label` | 终焉范围，如“第1次终焉”“第4-6次终焉” |
| `title` | 小标题，如“关系被强行启动” |
| `definition` | 一句话定义这一阶段的核心功能 |
| `core_characters` | 本阶段最关键的 2-4 个人物 |
| `core_events` | 本阶段最关键的 2-4 个事件 |
| `core_mechanics` | 本阶段最关键的规则/机制 |
| `stage_result` | 本阶段留下的结构性结果 |
| `next_stage_link` | 它如何流向下一阶段 |

### 3.3 总馆内容边界

总馆只保留主脉络，不展开细节，不做角色深描，不做规则百科。

总馆要避免：

- 把事件写成流水账
- 把人物写成百科卡
- 把世界观写成设定堆积

总馆应该像：

`馆内总导览地图`

而不是：

`主展厅本身`

### 3.4 总馆初始阶段建议

当前可先按这 7 段组织：

1. `终焉之前`
2. `第1次终焉`
3. `第2-3次终焉`
4. `第4-6次终焉`
5. `第7-10次终焉`
6. `第11次终焉以后`
7. `终局`

后续如果内容更扎实，可以再细拆；如果某些轮次信息少，也可以继续合并。

## 4. 人物馆定位

### 4.1 人物馆是什么

人物馆不是“角色介绍页”，而是 `人物深描馆`。

它的目标不是告诉用户“这个人是谁”，而是让用户理解：

- 这个人进入终焉时是什么状态
- 这个人经历了哪些关键变化
- 这个人的心理如何变化
- 这个人和别人的关系是如何被事件改写的
- 为什么这个人物会成为今天这个样子

人物馆是全站最适合放“人物厚度”的地方。

### 4.2 人物馆固定结构

每个人物固定使用 6 段式模板：

| 字段 | 说明 |
| --- | --- |
| `positioning` | 人物定位，一句话定义他在整部作品中的作用 |
| `initial_state` | 初始状态，进入终焉前后的基本精神状态和行为模式 |
| `key_event_path` | 只保留 3-5 个关键事件，不做流水账 |
| `psychological_arc` | 心理变化轨迹，按阶段写，而不是抽象评价 |
| `relationship_arc` | 关键关系变化，只保留最核心的 3-4 条 |
| `detail_specimens` | 人物细节标本：说话方式、选择偏好、恐惧反应、常见误读点等 |

### 4.3 人物馆推荐增强字段

为了做得更厚，可以再增加：

| 字段 | 说明 |
| --- | --- |
| `reader_consensus` | 网上常见的人物理解方向 |
| `debated_points` | 读者讨论较多的争议点 |
| `motif_keywords` | 这个人物对应的关键词，如“欺诈 / 共谋 / 执行 / 游离” |
| `linked_events` | 直接跳转到事件馆对应展品 |
| `linked_relations` | 直接跳转到关系馆中的关系类型 |

### 4.4 人物馆内容标准

人物馆必须避免两件事：

1. 纯设定堆砌  
2. 纯空洞赞美

人物馆要写成：

`人物经历了什么 -> 心里怎么变 -> 所以他和别人怎么变`

### 4.5 人物馆首批优先名单

第一批建议先做：

- 齐夏
- 林檎
- 乔家劲
- 陈俊南
- 甜甜
- 韩一墨

第二批再扩更重要的后续人物。

## 5. 事件馆定位

### 5.1 事件馆是什么

事件馆不是“剧情回顾”，而是 `事件剖面馆`。

每个事件都要回答：

- 谁参与了
- 游戏/规则是什么
- 事件是如何推进的
- 它改写了谁
- 它留下了什么
- 它在文学、博弈或结构上有什么值得看的地方

你前面提的“规则、知识、文学性都放进去”，我认为完全正确，而且这会让事件馆成为非常强的内容核心。

### 5.2 事件馆固定结构

每个事件统一使用 8 段式模板：

| 字段 | 说明 |
| --- | --- |
| `event_name` | 事件名 |
| `stage_range` | 所属终焉阶段 |
| `participants` | 参与人物 |
| `rule_set` | 事件规则、限制条件、胜负结构 |
| `process_summary` | 事件过程，要求简练，不做小说复述 |
| `impact_on_characters` | 这个事件改变了谁，如何改变 |
| `structural_result` | 留下了什么结果，如何流入后续 |
| `curator_note` | 策展批注：为什么这个事件重要 |

### 5.3 事件馆增强层

我建议每个事件再增加两层深度内容：

#### A. 知识补充

可以收录：

- 博弈论
- 囚徒困境
- 悖论
- 心理学机制
- 群体决策
- 文学意象
- 叙事结构作用

#### B. 规则剖面

可以单独整理：

- 规则明面是什么
- 真正的隐性压力是什么
- 谁最理解这套规则
- 谁在这套规则里吃亏

### 5.4 事件馆内容标准

事件馆不能只写“发生了什么”，而必须写：

- `事件机制`
- `人物影响`
- `结构后果`

### 5.5 事件馆首批优先事件

建议首批至少做：

- 第一间房试炼
- 伪同盟成形
- 临时合作出现
- 主角团雏形生成
- 关系震荡与重排
- 真相逼近

后续再扩展更具体的房间和关键局。

---

## 6. 世界观馆定位

### 6.1 世界观馆是什么

这里我建议不要叫“规则/真相馆”，直接叫 `世界观馆` 更稳。

因为它不只是讲规则，还讲：

- 终焉之地
- 轮回
- 回响
- 游戏机制
- 结构性压迫
- 世界的运转方式
- 终局如何回收前文

它是全站的 `解释层`。

### 6.2 世界观馆三层结构

建议拆成 3 层：

#### 规则层

收纳：

- 游戏规则
- 生存压力
- 信息差
- 惩罚机制
- 回响
- 风险放大

#### 结构层

收纳：

- 终焉之地
- 轮回结构
- 阵营/组织
- 系统性压迫
- “为什么人会被持续推入局中”

#### 真相层

收纳：

- 终局解释
- 真相节点
- 前文回收
- 前面所有关系和事件如何被重新理解

### 6.3 世界观馆固定字段

每个世界观节点建议统一为：

| 字段 | 说明 |
| --- | --- |
| `concept_name` | 概念名 |
| `layer` | 规则层 / 结构层 / 真相层 |
| `definition` | 核心定义 |
| `how_it_works` | 它如何在书中运作 |
| `affected_characters` | 它主要影响了谁 |
| `affected_events` | 它在哪些事件里具体体现 |
| `final_reinterpretation` | 到终局时它被如何重新解释 |

### 6.4 世界观馆内容标准

世界观馆要避免两件事：

1. 只罗列概念名词  
2. 只写抽象哲学话

必须做到：

`每一个概念都能连回具体人物和事件`

---

## 7. 关系馆定位

### 7.1 关系馆是什么

关系馆不是主导航，而是 `深度专题馆`。

它的价值不是给人认路，而是让读者看到《十日终焉》里最迷人的张力：

- 共谋
- 试探
- 保护
- 利用
- 背叛
- 压制
- 互补
- 串联

### 7.2 关系馆固定结构

关系馆不按人物排，也不按时间排，而是按 `关系类型` 排。

每一类关系固定使用以下字段：

| 字段 | 说明 |
| --- | --- |
| `relation_type` | 关系类型 |
| `definition` | 这一类关系在《十日终焉》里是什么意思 |
| `core_pairs` | 最典型的人物对/人物群 |
| `related_events` | 这类关系最明显出现在哪些事件中 |
| `psychological_basis` | 这种关系背后的心理基础是什么 |
| `how_it_changes` | 它在后续如何升级、扭曲或破裂 |

### 7.3 关系馆价值

关系馆最适合放“读者已经看完书，回来二刷”的内容。

它不是用来扫主线的，而是用来：

- 深看人物之间的张力
- 做人物馆与事件馆之间的横向联结
- 给网站增加“不是普通资料站”的深度感

## 8. 馆与馆之间的跳转逻辑

为了保证链路清晰，不建议做无限扩散式跳转，而要用固定的互联规则。

但根据最新要求，需要同时满足：

- `只要出现的条目之间都支持跳转`
- `条目很多时仍然清晰`

所以这里要改成：

`所有条目都支持跳转，但展示层只显示“推荐跳转”，深层层面保留“全部关联”。`

也就是说：

- 数据层：全条目互联
- 展示层：默认只显示最关键的几条
- 深层层面：可以展开查看全部关联

这是唯一能同时满足“全互联”和“清晰”的方式。

推荐跳转规则如下：

### 8.1 总馆跳转

总馆可以跳向：

- 当前阶段的核心人物
- 当前阶段的核心事件
- 当前阶段的核心机制

总馆不要直接跳太深，不要从总馆一步跳到非常细的小概念。

### 8.2 人物馆跳转

人物馆可以跳向：

- 该人物的关键事件
- 该人物的关键关系
- 该人物涉及的世界观节点

人物馆不要直接列出所有关系，只保留最关键的几条。

### 8.3 事件馆跳转

事件馆可以跳向：

- 参与人物
- 相关规则
- 该事件留下的结构性结果

事件馆是全站最重要的中转馆之一。

### 8.4 世界观馆跳转

世界观馆可以反向跳向：

- 受其影响的人物
- 体现该概念的关键事件
- 终局相关回收节点

### 8.5 关系馆跳转

关系馆可以跳向：

- 典型人物对
- 体现这类关系的关键事件
- 相邻关系类型

例如：

`共谋 -> 试探 -> 利用`

或

`保护 -> 牺牲 -> 代价`

### 8.6 全条目跳转总原则

从现在开始，所有馆内条目都默认具备跳转能力。

推荐统一跳转规则如下：

| 当前条目类型 | 必须可跳向 |
| --- | --- |
| 阶段 | 人物 / 事件 / 机制 / 阶段结果 |
| 人物 | 关键事件 / 关键关系 / 世界观节点 / 所属阶段 |
| 事件 | 参与人物 / 规则机制 / 结果结构 / 所属阶段 |
| 世界观节点 | 受其影响人物 / 体现该概念的事件 / 终局回收点 |
| 关系类型 | 典型人物对 / 关键事件 / 相邻关系类型 |
| 结果节点 | 产生它的事件 / 承接它的下一阶段 / 被它改写的人物 |

这里的关键不是“能不能跳”，而是：

`每一跳都必须有意义。`

所以后续录入时，每一条数据至少要带：

- `primary_links`
- `secondary_links`
- `deep_links`

推荐含义：

| 字段 | 含义 |
| --- | --- |
| `primary_links` | 默认展示的 2-4 个最关键跳转 |
| `secondary_links` | 展开后展示的扩展跳转 |
| `deep_links` | 数据层完整关联，用于搜索、反查、关系网模式 |

这样可以保证：

- 首页和普通浏览时不乱
- 深度探索时不会断
- 所有条目之间都能建立互联

## 9. 全站内容清晰性原则

为了保证你强调的“精简基础上的清晰”，全站必须遵守以下规则：

### 9.1 一个馆只回答一种核心问题

| 馆 | 核心问题 |
| --- | --- |
| 总馆 | 故事怎么推进 |
| 人物馆 | 这个人如何变化 |
| 事件馆 | 这件事如何改写人物和结构 |
| 世界观馆 | 为什么会这样，以及终局如何解释 |
| 关系馆 | 人与人之间怎么缠住 |

### 9.2 一条内容只保留最必要的关联

不要给一个人物挂 20 个事件，也不要给一个事件挂 15 条关系。

建议控制：

- 人物页：3-5 个关键事件
- 人物页：3-4 条关键关系
- 事件页：2-5 个关键参与者
- 世界观页：2-4 个典型事件链接

### 9.3 每条内容都要有“主字段”

任何条目都必须有一个最重要字段：

- 人物页的主字段：`心理变化`
- 事件页的主字段：`改变了谁`
- 世界观页的主字段：`如何作用于人物与事件`
- 关系页的主字段：`这类关系如何形成和变形`

为了避免一开始失控，建议按这个顺序补数据：

- 完成总馆阶段表
- 完成人物馆首批人物

- 补世界观馆的规则层和结构层

## 12. 核心人物补全原则

根据最新要求，人物馆不能只停留在“第一间房主角团”，而要补到整部作品中真正构成主脉络的核心人物群。

这里建议采用 `三级人物池`，而不是一口气不分层全部塞平。

### 12.1 一级人物：主脉络人物

这部分必须优先完成，属于网站第一批正式内容核心。

目前结合现有仓库数据和线上高频讨论，建议至少包括：

- 齐夏
- 林檎
- 乔家劲
- 陈俊南
- 甜甜
- 韩一墨
- 许流年
- 楚天秋
- 燕知春
- 章晨泽
- 云瑶
- 李尚武
- 肖冉

### 12.2 二级人物：强关联关键人物

这部分是主线的扩展支点，建议在一级人物稳定后补入。

当前线上讨论中出现较多、可作为二级候选的人物包括：

- 张强
- 郑英雄
- 舒画
- 金元勋

以及后续查证后确认的重要阵营人物、生肖人物、组织人物。

### 12.3 三级人物：专题人物 / 事件人物

这部分不一定都进人物馆首页，但应保留为数据库条目，并能从事件馆、关系馆或世界观馆跳到。

适合纳入：

- 仅在特定事件中起关键作用的人物
- 组织性人物
- 终局回收时重要但前期出场不重的人物

### 12.4 人物补全标准

不是“只要有名字都建人物页”，而是满足以下任一条件就纳入：

1. 对主脉络推进有明显作用
2. 对某一阶段结果产生决定性影响
3. 在读者讨论中具备高频辨识度
4. 能代表一种重要关系类型
5. 能代表一种重要世界观机制

---

## 13. 人物馆资料来源建议

为了把人物馆做厚，后续人物内容不只依赖现有仓库文案，建议采用三类来源交叉整理：

### A. 原文主线信息

用于保证：

- 人物轨迹准确
- 关键事件不偏
- 心理变化不失真

### B. 读者高频讨论信息

用于补足：

- 人物常见理解角度
- 争议点
- 角色魅力来源
- 哪些细节最被反复提到

当前可参考的讨论来源类型包括：

- B站人物分析视频
- B站人物盘点 / 阵营分析
- 贴吧“人物总结”“全本资料”“时间线讨论”
- 豆瓣长评中的人物解读

### C. 结构化整理信息

用于补足：

- 阵营划分
- 回响整理
- 游戏/事件与人物的对应关系
- 人物与终局回收的连接

## 14. 对网站结构的最终建议

如果只保留一句最重要的建议，就是：

`总馆负责把故事排顺；人物馆负责把人写厚；事件馆负责把局拆透；世界观馆负责把整个终焉结构解释清楚；关系馆负责给深度读者提供二刷价值。`

这 5 个馆里，最该优先投入内容的是：

1. `人物馆`
2. `事件馆`
3. `总馆`

因为用户真正停留时间最长的，会是人物和事件，而不是大纲。
